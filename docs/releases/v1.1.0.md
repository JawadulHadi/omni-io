**Deployment hardening and security fixes.** The build is green again on the upgraded dependencies, the whole stack deploys to one server with one command, and two security issues from 1.0.0 are fixed. **Everyone on 1.0.0 should upgrade.**

## Security

- **Google sign-in could take over password accounts.** 1.0.0 linked a Google identity to any existing password account with the same email. Because sign-up doesn't verify email ownership, whoever registered an address first could keep access to the real owner's account. Google sign-in now refuses to link, and the console sends the user to password sign-in.
- **Anonymous widget visitors could receive internal FAQ answers** from Tier 3. FAQs now have a visibility setting. Existing FAQs stay public, and new ones start internal.

## Highlights

- **One-command deployment.** [`deploy/`](https://github.com/JawadulHadi/omni-io/tree/v1.1.0/deploy) runs Postgres + pgvector, Redis, the API, the ingestion worker and Caddy with automatic HTTPS: `cp .env.example .env && docker compose up -d --build`. Migrations run first, as the schema owner. CI builds both production images.
- **Invite links** replace `inviteMember`. They are single-use, valid for 7 days, and accepted by the invitee. With `ALLOW_SIGNUP=false`, they are the only way to create an account.
- **Personal access tokens for MCP** (`omni_pat_…`), managed in the console and accepted only on `/mcp`.
- **MCP tool metadata.** Every tool declares a title, an input schema and all four annotation hints, so MCP clients can warn before `ask_question` spends budget or calls the model provider.
- **Cost ceilings:**
  - a daily model-call budget per workspace (Tier 2 answers after it, not errors);
  - per-user question limits;
  - per-workspace upload limits;
  - a cap on workspaces per user.
- **A grounding check on Tier 1.** Enough of the answer's words must appear in the passages it cites (`tier1_ungrounded`).
- **Answer-audit retention**, default 90 days, enforced by the worker.

## Resilience fixes

- The question embedding now has its own timeout and circuit breaker. Before, a hanging embedding API hung every question.
- The half-open circuit breaker lets exactly one probe through, instead of every concurrent request.
- With Postgres down, the widget answers with the hand-off message instead of a 500.
- With Redis down:
  - rate limits fall back to per-process counters instead of hanging;
  - uploads are saved as `failed` with a Retry button.
- PDF parsing runs in a worker thread with a 30-second limit and a 512 MB heap cap.
- Vector search falls back to an exact per-tenant search when HNSW's iterative scan comes back short.
- Removed members stop receiving live ingestion events immediately.
- `/health` reports Postgres and Redis separately. It returns 200 `degraded` without Redis and 503 without Postgres.

## Upgrading from 1.0.0

1. Use Node 24 LTS for development. The app runs on 22.12+, and the unit tests need 24.9+.
2. Run migrations: `npm run migrate` (or `node dist/migrate.js`). This applies `0004_hardening.sql`.
3. Remove `APP_USER_CONNECTION_KEY_SECRET` from your environment; it is no longer read.
4. Review the new settings in `.env.example`:
   - `ALLOW_SIGNUP`
   - the `*_LIMIT_*` cost ceilings
   - `ANSWER_RETENTION_DAYS`
   - `STORAGE_DRIVER` (default `none`: originals are no longer kept)
   - `DB_STATEMENT_TIMEOUT_MS`
5. In production, the API now refuses to start with `COOKIE_SECURE=false` or the example `JWT_SECRET`.
6. GraphQL clients: replace `inviteMember` with `createInvitation` / `acceptInvitation`.

## Known limitations

- Circuit breakers are per API instance; a shared Redis breaker is planned.
- No email verification yet. Run with `ALLOW_SIGNUP=false` in production.
- MCP uses bearer tokens; OAuth 2.1 is planned.
- There are no built-in backups. Back up the `pgdata` volume, or use managed Postgres snapshots.
