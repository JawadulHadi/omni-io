**The first stable release of Omni.io.** It is a multi-tenant AI customer-support engine that degrades gracefully instead of failing. This release adds the admin console, the embeddable widget, the documentation set and CI on top of the hardened backend from v0.2.0.

![Playground](https://raw.githubusercontent.com/JawadulHadi/omni-io/v1.0.0/docs/assets/screenshots/playground.png)

## Highlights

- **Admin console** (React 19, Tailwind v4, shadcn/ui, urql), with eight lazily loaded screens:
  - **Playground:** tier badge, verified citations, the full decision trace, ladder settings, and one-click failure injection.
  - **Documents:** drag-and-drop upload, paste, public/internal visibility, live embedding progress, retry, GDPR erasure.
  - **Ingestion:** live queue.
  - **FAQs:** the Tier 3 floor.
  - **Members:** role management with escalation rules.
  - **Widget:** theme, key rotation, embed snippet.
  - **Answer audit:** tier distribution, token totals, an expandable decision trace per answer.
  - **Sign-in:** email or Google.
- **Session handling:** the access token lives in memory and the refresh token in an httpOnly cookie. Refreshes are single-flight within a tab and serialized across tabs with Web Locks, because refresh-token reuse revokes the session.
- **Embeddable widget:** a standalone `widget.js` (~72 kB gzipped) that renders in a Shadow DOM, calls the API with absolute URLs, ships as an ASCII-only bundle, and has designed states for rate limiting and key rotation. A hosted chat page is served at `/w/:key`.
- **Brand:** the Omni.io mark (three rungs, widest first) used in the console, the favicon and the docs.
- **Docs:**

  - [resilience ladder](https://github.com/JawadulHadi/omni-io/blob/v1.0.0/docs/resilience-ladder.md)
  - [multi-tenancy](https://github.com/JawadulHadi/omni-io/blob/v1.0.0/docs/multi-tenancy.md)

  - a [sample knowledge base](https://github.com/JawadulHadi/omni-io/tree/v1.0.0/samples)
- **Project health:** CI (typecheck, unit tests, RLS integration against pgvector, both frontend bundles), Dependabot, issue and PR templates, and security, contribution and conduct policies.

## Fixed during end-to-end browser verification

- Chunks could start mid-word; both chunk boundaries now land on whitespace.
- PDF page markers (`-- 1 of N --`) no longer leak into chunks and citations.
- Widget glyphs no longer render as mojibake on host pages that don't declare UTF-8.
- The fake provider now gives extractive, question-relevant answers, so offline demos read like real ones.

## Upgrading from 0.2.0

- Rebuild the frontend: `npm run build` now produces the console, the hosted widget page and `dist/widget.js`.
- Serve `/w/<key>` page loads from `widget.html`, and send `/w/<key>/ask` and `/w/<key>/config` to the API ([deployment guide](https://github.com/JawadulHadi/omni-io/blob/v1.0.0/docs/deployment.md)).
- Set `VITE_API_BASE` if the API is on another origin. It must be the same site, because the refresh cookie is `SameSite=Strict`.

## Known limitations

- The circuit breaker is per API instance.
- Upload storage uses a local-disk driver (the `BlobStorage` interface is ready for S3 or GCS).
- MCP uses bearer-token auth; OAuth 2.1 is planned.
- Confidence thresholds are tuned by hand; an evaluation set is planned.
