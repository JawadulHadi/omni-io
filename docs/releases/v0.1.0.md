**The starting point: the NestJS/React scaffold generated from the Omni.io architecture spec.** Kept in history so the path to v1.0.0 is visible. Don't deploy it; use [v1.0.0](https://github.com/JawadulHadi/omni-io/releases/tag/v1.0.0).

## What's in it

- A NestJS module layout covering auth, workspaces, documents, ingestion, answers, FAQs, widget, audit and MCP, with raw `pg` services.
- A first SQL migration: tables, RLS policies, a `match_chunks` pgvector function.
- A first draft of the three-tier resilience ladder (`AnswerService`).
- BullMQ ingestion producer and consumer, with fixed-size chunking.
- An AES-256-GCM helper for connector secrets.
- A React 19 + Vite shell with a playground page and a widget component.
- The original architecture spec.

## Known issues

A full review found **35 implementation issues and 12 spec issues**. It is published in [docs/reviews/2026-09-29-scaffold-review.md](https://github.com/JawadulHadi/omni-io/blob/main/docs/reviews/2026-09-29-scaffold-review.md). The most serious:

- **It does not build, migrate or boot.** Missing type packages, a deprecated migration command, and no GraphQL resolvers.
- **Row-level security enforces nothing.** The app connects as a Postgres superuser, and the tenant setting is dropped before any query runs.
- **The "never errors" ladder returns HTTP 500 for every question**, because the embedding call has no error handling.
- **Refresh tokens work as 30-day access tokens.**

All of these are fixed in v0.2.0 and v1.0.0.
